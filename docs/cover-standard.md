# 封面规范（Cover Standard）

本站所有文章封面统一遵循本规范。新增文章、修改封面、AI 校对时都以此为准。

---

## 1. 硬性规格

| 项 | 值 | 说明 |
| --- | --- | --- |
| 尺寸 | **1200 × 630** | 严格 40:21，与 Chirpy 首页卡片 `aspect-ratio: 40/21` 完全一致，不会被裁切 |
| 格式 | **WebP** | 不用 GIF（首页多图会同时播放，视觉噪音大）、不用 PNG（体积大 3~5 倍） |
| 体积 | **≤ 80KB** | 当前 5 张实测 4.9–9.7KB，超出说明构图过于复杂或用了位图 |
| 文件名 | `cover.webp` | 固定命名，按文章 slug 归档 |
| 位置 | `assets/img/posts/<slug>/cover.webp` | — |

> 为什么是 40:21 而不是 16:9：Chirpy 的缩略图容器是 `aspect-ratio: 40/21` + `object-fit: cover`，比例不符会被裁掉边缘。1200×630 恰好等于 40:21。

---

## 2. 视觉令牌

固定使用，不要逐图调整。

```
背景渐变    #0c0e13 → #121722 → #0a1219（对角，左上下右）
网格        #ffffff，透明度 0.03，40×40
光晕        #5eead4 18% + #4aa8ff 7%，椭圆居中偏右
主强调色    #5eead4（teal）
辅强调色    #4aa8ff（blue）
起点标记    #34d399（green）
终点标记    #fb923c（orange）
分类角标    #68758a，13px，letter-spacing 4，左下 (72, 562)
品牌角标    #4e5867，13px，letter-spacing 6，右下 (1128, 562)
字体        Segoe UI, Arial, Helvetica, sans-serif
```

深色封面是**有意选择**：在浅色主题下作为视觉锚点，在深色主题下与页面融合。不做双套封面。

---

## 3. 构图规则

- **主体中心在 x ≈ 740、y ≈ 310**，即画面中线偏右，而不是贴右下角
- 主体占画面宽度 **55%–65%**，四周留白 ≥ 40px
- **不放文章标题文字**。封面在首页会缩到 300–450px 宽，任何小于 40px 的字都会糊成色块
- 只允许两类文字：左下分类角标（英文大写）、右下品牌角标
- 一篇文章一个**单一母题**，不要把多个概念堆在同一张图里
- 主体不得侵入底部角标区（y > 540）

## 4. 母题库

| 文章 | 母题 | 关键元素 |
| --- | --- | --- |
| 排序算法 | 递增柱阵 | 12 根圆角柱，左低右高，青色渐变，底部基线 |
| 寻路算法 | 网格路径 | 18×9 点阵，阶梯折线，绿起点 + 橙终点带光环 |
| 从 Transformer 到 Agent | 网络收敛为链 | 三层节点网络 → 箭头 → 三个链式圆角矩形 |
| RoughAgent | 三栏桌面 | 窗口框 + 左会话条 + 中对话气泡 + 右数据条与环形进度 |
| RoughEngine | 透视场景 | 透视地面网格 + 线框立方体 + 三色坐标轴 |
| 手搓 vs AI | 波形收敛 | 左侧橙色不规则抖动笔画 → 右侧青色等宽方波，渐变描边 |

新增文章时，在 `tools/cover/gen.js` 里加一个母题函数，并从上面六张里选一个最接近的视觉语言复用。

配色语义（长期保持，不要随意换）：
- 青色 `#5eead4`：主强调、系统/机器一侧
- 蓝色 `#4aa8ff`：信息、结构
- 橙色 `#fb923c`：人为一侧、终点/警示

---

## 5. 禁止项

- ❌ **不使用软件 UI 截图**作封面（信息密度过高，缩略后细节全糊，与极简版式冲突）
- ❌ 不使用 GIF 作封面
- ❌ 不使用白底或浅底封面
- ❌ 不在封面内放中文标题、正文小字、水印
- ❌ 不使用 AI 生成插画（风格不可控，且中文字极易出现乱码）
- ❌ 不做圆角或描边外框（Chirpy 卡片本身已有圆角，重复会显脏）

---

## 6. front matter 写法

推荐使用 `media_subpath`，路径更短、迁移方便：

```yaml
media_subpath: /assets/img/posts/<slug>
image:
  path: cover.webp
  alt: 一句准确描述画面母题的话
```

`alt` 会被用于 `og:image:alt` 与图片无障碍描述，必须描述**画面内容**，而不是文章标题。

---

## 7. 生成流程

```bash
# 1. 在 tools/cover/gen.js 增加或修改母题函数
# 2. 生成 SVG
node tools/cover/gen.js

# 3. 转 WebP（sharp-cli 首次运行会自动下载）
npx --yes sharp-cli -i tools/cover/out/<name>.svg -o assets/img/posts/<slug>/cover.webp

# 4. 目视检查（必须做）
#    用看图工具确认：无越界、无重叠、缩到 300px 宽仍能辨识母题
```

脚本只依赖 Node，无 Ruby/ImageMagick 要求。

---

## 8. 校对清单

AI 校对文章或封面时，逐项检查：

- [ ] 尺寸严格 1200×630（解析 WebP 文件头，不要只看文件名）
- [ ] 体积 ≤ 80KB
- [ ] 文件名为 `cover.webp`，位于对应 slug 目录
- [ ] 画面是抽象图形，不含 UI 截图、GIF 帧、白底
- [ ] 无正文小字、无中文标题文字
- [ ] 主色落在 `#5eead4` / `#4aa8ff` 区间，背景为深色渐变
- [ ] 主体中心在 x≈740，未贴边、未压到角标
- [ ] 缩略到 300px 宽仍可辨识母题
- [ ] front matter 的 `alt` 与画面一致
- [ ] 正文没有对旧封面文件的引用（旧图可留档，但不得再被引用）
