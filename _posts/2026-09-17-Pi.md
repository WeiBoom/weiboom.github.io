上一篇《[RoughAgent-属于自己的Harness工具](/posts/RoughAgent/)》讲的是我做了什么：把 AI 的账单拆到像素级、三个壳共用同一个它、右下角那只叫丢丢的狗。

这篇讲的是它跑在什么上面。RoughAgent 的内核不是我写的，我用的是 **Pi**。

Pi 是一个极简、可扩展的终端 Agent：MIT 协议，TypeScript，作者 Mario Zechner（公司 Earendil Inc.），仓库在 [earendil-works/pi](https://github.com/earendil-works/pi)，官网 [pi.dev](https://pi.dev)，我用的版本是 v0.87.1，现在 10.9 万 star。

官网首屏有两句话，我第一次看没什么感觉；做完 RoughAgent 再看，觉得它把话说得很准：

> There are many agent harnesses but this one is yours.
>
> Pi is a minimal agent harness. Adapt Pi to your workflows, not the other way around.
>
> （Harness 有很多，但这一个是你的。Pi 是一个极简的 agent harness——让 Pi 适应你的工作流，而不是反过来。）

## 一、Pi 是什么

### 它给的是地基，不是装修

Pi 提供的东西不多，但都是承重的：统一的 LLM API、agent loop、会话存储、终端界面（TUI）、命令行工具，以及一套 TypeScript SDK。循环怎么转、上下文怎么拼、会话怎么存、工具怎么执行，这些它做扎实；界面长什么样、钱怎么花、权限怎么管，它不插手。

从安装方式也能看出它的性格：一个 npm 包就行（`npm install -g @earendil-works/pi-coding-agent`，要求 Node 22.19 以上），官方还专门说明它**不需要依赖的生命周期脚本**。跑起来就是 `cd 你的项目 && pi`。

它有五种用法：TUI 交互、print 一次性、JSON 事件流、RPC 跨进程、TypeScript SDK 同进程。关键是——**这五种入口走的是同一套 agent 与 session 机制**。

![一套内核，五种接口](pi-interfaces.webp)
_一套机制、多种入口：RoughAgent 的三端之所以能成立，是因为内核本来就这么设计的_

### system prompt 为什么能这么小

内核要省 token，第一步就是别把一大堆东西塞进 system prompt。Pi 的做法是：system prompt 由**基础指令 + 被发现的上下文文件**（比如项目里的 `AGENTS.md`、`~/.pi/agent/AGENTS.md`）组成；**技能的正文按需加载**——先只放名字和描述，真要用到再去读正文。扩展可以追加指令或变换上下文，prompt templates 则在输入变成消息之前先展开。

这件事的意义，上一篇里我说了一半：**前缀要恒定**。这里补上另一半：**前缀还要小**。恒定但庞大，账单照样重。Pi 把“小”做成了默认值，而不是让我自己去删。

### 一次请求在内核里怎么走

按官方文档（how-pi-works）的描述：你发的消息进入当前活动分支；Pi 用 system prompt、活动分支、可用工具和模型设置组装出一次请求，交给选定的 provider；provider 流式返回文本和工具调用；Pi 记录回复、逐个执行工具调用、记录结果——到这里是一个 turn。如果工具结果或排队消息还需要模型再动一次，就再来一个 turn；不需要，这一轮结束。

里面有三个语义，直接决定交互手感，我特别喜欢：

- **steering**：运行中按 Enter，消息插在当前 assistant turn 和它的工具调用之后——“方向不对，往左”；
- **follow-up**：Alt+Enter，等这一轮的待办全做完再进来——“顺带把那个也改了”；
- **abort**：停掉当前 run，并把排队但还没发出去的消息**还给你**，不吞你的输入。

写过 agent 的人大概都踩过：纠正被当成下一轮的新问题，或者打了半天的字消失了。

### 会话是一棵树，不是一个列表

Pi 的会话是 JSONL 文件。每个条目有 id，并指向自己的父条目；从当前条目往回走出来的那条路径，就是这次请求的上下文——**每条路径都是一个分支**。

所以“回到某条消息重新开始”“从某一步分叉出去试另一个方向”“把整段会话导出分享”，都是内核自带的能力，不是上层应用拼出来的。上下文压缩（compaction）也不是删旧消息：它往树里**插一条摘要条目**，让之后的请求用摘要替换掉更早的消息，原始条目仍然留在树里。

![Pi 的会话树视图：工具调用被折叠成一行行](pi-tree-view.webp)
_会话树：每条支线都在，工具调用收成一行，连被中止的那次 assistant 回复也留在记录里。（图自 Pi 官方文档）_

## 二、我为什么把它当内核

### 1. 它天生就小，对前缀缓存友好

上一篇里我讲过**缓存锚纪律**：凡是要进请求前缀的东西都必须恒定，因为前缀缓存按字节匹配，变一个字节就整段全额付费。

Pi 的官方介绍里有一句我特别认同的话：它“支持 skills 和 AGENTS.md，并且因为 system prompt 极简而**非常省 token**”。这两件事其实是同一件事的两面——**一个极简的 system prompt，本身就是对前缀缓存最友好的地基**。我在这之上要做的，只是别往里塞动态的东西（时间戳、随机 id、随会话增减的工具表）。要是内核自己就拖着一大坨会变的前缀，我上面再怎么小心都没用。

![Pi 的交互界面：启动时列出加载的 Context / Skills / Prompts / Extensions / Themes，页脚是这一轮的实时用量](pi-interactive-mode.webp)
_启动清单之后，页脚一行就是这一轮的全部账：↑输入 ↓输出 R 缓存读 CH 缓存命中率 $ 花费。（图自 Pi 官方文档）_

### 2. 该给的边界，它都做成了接口

Pi 的 SDK（`@earendil-works/pi-coding-agent`）直接在 Node 或 Bun 进程里跑。官方文档里的最小例子就是这几行：

```typescript
import { createAgentSession } from "@earendil-works/pi-coding-agent";

const { session } = await createAgentSession();

try {
  await session.prompt("这个项目里有什么？");
  console.log(session.getLastAssistantText());
} finally {
  session.dispose();
}
```

但真正让我决定用它的是它把**边界**都做成了可注入的东西：模型（`modelRuntime` / `model` / `thinkingLevel`）、设置（`settingsManager`）、会话（`sessionManager`，可以做成纯内存的）、资源发现（`resourceLoader`：扩展、技能、提示模板、主题、上下文文件）、工具集（`tools` / `noTools` / `excludeTools` / `customTools`）。会话层还有 `newSession` / `switchSession` / `fork` / `importFromJsonl`；事件流里能拿到消息增量、工具执行、压缩、重试，还有一个 `agent_settled`——内核明确告诉你“它不会再自动往下跑了”。

这些名字看着枯燥，但它们回答了一个很实际的问题：**如果我要接管某一层，内核有没有给我口子。** 它不是给我一个黑盒，而是一层一层列出来。于是 RoughAgent 的界面、状态、策略全在我这边，循环、工具执行、上下文压缩全在内核那边。

### 3. 五种接口，一套机制

RoughAgent 的三端不是把内核抄了三遍：

- **桌面端**（Tauri）走 SDK，内核跑在同一个进程里，界面能直接订阅事件流；
- **浏览器和终端**接同一个本地服务，走的是 RPC，会话还是同一份；
- 脚本和定时任务走 print 或 JSON 模式。

因为内核保证“五种入口共用同一套 agent 与 session 机制”，我不用自己发明跨端协议，也不用把会话在三个地方各存一份。上一篇里说的“三个壳，同一个它”，严格讲不是我设计的，是我选对了地基。

### 4. 不改源码，也能长出能力

Pi 的扩展面有五种：**extensions**（TypeScript 模块，可以注册工具、命令、快捷键、provider、事件处理器、渲染器、终端 UI）、**skills**（按需加载的指令）、**prompt templates**（可复用的消息）、**themes**（终端配色）、**packages**（用 npm 或 git 分发以上资源）。生态里已经有第三方扩展在跑，比如能画图的 `@termdraw/pi`。

一个最小的扩展长这样（官方文档里的例子）：

```typescript
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.registerCommand("hello", {
    description: "Show a greeting",
    handler: async (name, ctx) => {
      ctx.ui.notify(`Hello, ${name || "world"}!`, "info");
    },
  });
}
```

存成一个 `.ts` 文件就行：Pi 用 jiti 直接加载 TypeScript，不需要单独编译，开发时 `pi --extension ./hello.ts` 立刻生效。官方仓库里带了一批量级例子：改页脚、改头部、自定义压缩策略、确认危险命令、退出时自动提交、书签、内置工具的渲染器，甚至自定义模型 provider。

RoughAgent 那 11 个能力域插件，全部走这套面，**内核一行源码没动**。所以才有了上一篇里那句话：内核被整体替换的那天，前端 38 项测试零改动全过。

我在这件事上不太愿意让步：**内核和应用之间必须有一条能被测试守住的线**。这条线平时看不见，但它决定了这个项目能不能活过半年。

## 三、边界：Pi 不做的，我在上面补

Pi 的官方 Security 文档写得很直白：工具和扩展**以 Pi 进程的操作系统权限运行**；项目信任（project trust）只决定加载哪些项目资源，**它不是沙箱**。扩展就是加载进 Pi 进程的 TypeScript 模块。

这不是缺陷，是定位。内核不该替你决定什么算危险——每个人对危险的边界不一样。但它也说清了一件事：内核之上必须有人管几件事。所以在 RoughAgent 这一层，我补了：

- **审批**：分级 + fail-closed。桥没挂上就拒，120 秒没响应就拒，一个回合收尾了还没批的统一拒；
- **上下文瘦身与跨会话记忆**：内核负责压缩，我负责“什么值得留”；
- **账单与预算线**：内核给用量，我给可读的一屏和超支提醒。

![分界线：机制归内核，策略归应用](pi-boundary.webp)
_内核管“能做什么”，应用管“允许做什么、该记住什么”——两侧只通过扩展面和 SDK 相接，内核一行源码都不改_

一句话：**内核管机制，应用管策略。** 这条线画清楚了，两边都轻松。

## 四、它和另外两家的差别

写这篇的时候，我特意把两个常被一起提到的开源 harness 看了一遍：**opencode**（对比它的 v2）和 **DeepSeek Harness**（DSH）。三家都是 MIT、都是 TypeScript，而且都很能打。差别不在好坏，在**它们各自假设你要做什么**。

| | Pi | opencode v2 | DeepSeek Harness |
|---|---|---|---|
| 假设你是 | 想自己造 Agent 应用的人 | 想马上开始写代码的人 | 想把一切拆成插件的人 |
| 形态 | 内核 + 五种接口 + SDK | 成品应用：TUI、桌面端、Web、服务端 | 插件树：连 agent loop、会话日志、模型适配器都是插件 |
| 扩展方式 | extensions / skills / prompts / themes / packages | 插件 + 内置 agents（build 全权限 / plan 只读 / general 子代理）+ 权限档位 | Cordis 插件：服务、类型化事件、可逆副作用，用 profile / bundle / patch 组装 |
| 会话 | JSONL 树：分支、fork、compaction 摘要 | 会话加 agent 切换 | 会话日志本身也是插件 |
| 嵌入方式 | TS SDK（同进程）、RPC（跨进程）、print、JSON | SDK、server、桌面端 | sdk（JSON-RPC）、headless、acp 三种 profile |
| 版本与规模 | v0.87.1，★10.9 万 | 正式版 v1.18.32，v2 在 v2 分支，★21.0 万 | developer preview（dsh-v0.1.7-rc），★23.6 万 |

**opencode v2** 走的是成品路线。它连桌面端都替你打包好了（dmg / exe / deb / rpm / AppImage / brew cask / scoop），内置 build（全权限）和 plan（默认不许改文件、跑 bash 要你点头）两个 agent，外加一个 general 子代理；monorepo 里有几十个包——tui、desktop、web、console、server、sdk、plugin。如果你要的是“今天就能干活”，它比 Pi 省事得多。我要的是“内核加我自己写壳”，它的体量对我来说大了一号。

**DeepSeek Harness** 走的是万物皆插件路线，最激进也最优雅。它建在 Cordis 上：模型适配器、工具注册表、会话日志、甚至 agent loop 本身都是插件，官方原话是“没有需要打补丁的特权内核”，并且带 web / headless / sdk / acp 几种 profile 可以组装。它是我最喜欢看的那类设计，但我没选它当底座，两个原因：一是它明确处于 developer preview，官方自己写着**会有破坏兼容的改动**；二是它的强大来自“一切都能替换”，而我要的是一个**稳定的地基**——我不想在选内核这件事上，再叠一层我自己的组装决策。

**Pi 在中间**：比 opencode 小一号，比 DSH 保守一号。内核稳定、边界清楚、接口够多、扩展面够用，而且它自己就是一个我天天在用的终端 Agent——我用它的 TUI 写代码，用它的 SDK 做 RoughAgent。

---

## 五、最后

官网那句“this one is yours”，我越用越有感觉。一个 harness 好不好，不看它的功能列表有多长，看它**有没有留出足够的空位让你放自己的东西**。

RoughAgent 就是那句话的产物：Pi 提供循环、会话、工具、模型；RoughAgent 提供界面、账单、审批、桌宠。中间那条线，是一条能被测试守住的线。

石头还在磨。至少底座是稳的。
