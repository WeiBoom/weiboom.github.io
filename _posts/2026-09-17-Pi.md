RoughAgent 的内核是 Pi。本文分五部分：Pi 的组成与机制、选型理由、内核不提供的部分、与其他 harness 的对比、基于 Pi 的项目。

## 一、Pi 是什么

### 定位与基本信息

| 项 | 值 |
|---|---|
| 仓库 | `earendil-works/pi` |
| 官网 | pi.dev |
| 协议 | MIT |
| 语言 | TypeScript |
| 作者 | Mario Zechner（Earendil Inc.） |
| 当前版本 | v0.87.1 |
| Star | 10.9 万 |
| 官方描述 | AI agent toolkit：unified LLM API、agent loop、TUI、coding agent CLI |

仓库 README 的定位句是：*Pi is a minimal, extensible AI agent for the terminal. Adapt Pi to your workflow, not the other way around.*（极简、可扩展的终端 agent；让 Pi 适应你的工作流，而不是反过来。）

### 组成与安装

组成：统一的 LLM API、agent loop、会话存储、终端界面（TUI）、命令行工具、TypeScript SDK。

安装方式为 npm 包（要求 Node 22.19 以上）：

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
cd <project> && pi
```

官方说明该安装不需要依赖的生命周期脚本。

### 五种接口

TUI 交互、print（单次任务）、JSON 事件流、RPC（跨进程）、TypeScript SDK（同进程）。五种入口共用同一套 agent 与 session 实现。

![一套内核，五种接口](pi-interfaces.webp)
_五种入口共用同一套 agent 与 session 机制_

### system prompt 与按需加载

system prompt 由基础指令与发现的上下文文件组成（例如项目内的 `AGENTS.md`、`~/.pi/agent/AGENTS.md`）。技能（skills）的正文按需加载，初始只加载名称与描述。扩展可以追加指令或改写上下文，prompt templates 在输入转为消息之前展开。请求同时携带工具定义与技能描述。

### 一次请求的执行流程

消息进入活动分支；Pi 用 system prompt、活动分支、可用工具与模型设置组装请求，交给选定的 provider；provider 流式返回文本与工具调用；Pi 记录回复，逐个执行工具调用并记录结果。以上构成一个 turn。若工具结果或排队消息需要再次请求模型，则进入下一个 turn。

三种消息语义：

- **steering**：运行中按 Enter，消息插在当前 assistant turn 及其工具调用之后；
- **follow-up**：Alt+Enter，等当前回合的待办完成后再进入；
- **abort**：停止当前 run，并将排队但未发出的消息返回编辑器。

### 会话模型

会话存储为 JSONL 文件。每个条目有 id，并引用其父条目；从当前条目回溯得到的路径是活动分支，也是下一次请求的上下文。分支、fork、clone 都是文件格式内的操作。

压缩（compaction）插入一条摘要条目，覆盖更早的消息参与后续请求，原始条目保留在文件中。

![会话树视图](pi-tree-view.webp)
_会话树：工具调用折叠为单行，被中止的 assistant 回复同样保留_

## 二、选型理由

### 1. system prompt 小，前缀稳定

官方介绍：Pi 支持 skills 与 AGENTS.md，system prompt 极简，token 效率高。

这与缓存命中直接相关：前缀缓存按字节匹配，前缀需要同时满足“小”和“恒定”。内核默认给出小的前缀，应用层需要做的是不在前缀里加入动态内容（时间戳、随机 id、随会话增减的工具表）。若内核自带较大的可变前缀，上层无法通过优化抵消。

![交互界面与用量页脚](pi-interactive-mode.webp)
_启动时列出加载的 Context / Skills / Prompts / Extensions / Themes，页脚为当前轮次的用量_

### 2. 可替换的边界

SDK（`@earendil-works/pi-coding-agent`）在 Node 或 Bun 进程内运行。官方文档的最小示例：

```typescript
import { createAgentSession } from "@earendil-works/pi-coding-agent";

const { session } = await createAgentSession();

try {
  await session.prompt("这个项目里有什么？");
  console.log(session.getLastAssistantText());
} finally {
  session.dispose();
}
```

可注入的边界包括：模型（`modelRuntime` / `model` / `thinkingLevel`）、设置（`settingsManager`）、会话（`sessionManager`，支持纯内存）、资源发现（`resourceLoader`：扩展、技能、提示模板、主题、上下文文件）、工具集（`tools` / `noTools` / `excludeTools` / `customTools`）。会话层提供 `newSession` / `switchSession` / `fork` / `importFromJsonl`；事件流包含消息增量、工具执行、压缩、重试，以及表示“内核不会自动继续”的 `agent_settled`。

对应用层的意义：界面、状态与策略留在应用层，循环、工具执行与上下文压缩留在内核。

### 3. 一套机制，五种入口

RoughAgent 的三种界面（桌面端 GUI、浏览器 Web、终端 TUI）由这套接口实现：

| 端 | 接入方式 |
|---|---|
| 桌面端（Tauri） | SDK，内核运行在同一进程，界面直接订阅事件流 |
| 浏览器、终端 | RPC，连接同一个本地服务，共用同一份会话 |
| 脚本、定时任务 | print 模式或 JSON 事件流模式 |

由于内核保证五种入口共用同一套 agent 与 session 机制，应用层不需要自定义跨端协议，也不需要重复存储会话。

### 4. 扩展面足以表达策略层

Pi 提供五种扩展形态：

| 形态 | 内容 |
|---|---|
| extensions | TypeScript 模块，可注册工具、命令、快捷键、provider、事件处理器、渲染器、终端 UI |
| skills | 按需加载的指令 |
| prompt templates | 可复用的消息模板 |
| themes | 终端配色 |
| packages | 以上资源的分发方式（npm 或 git） |

扩展由 jiti 直接加载，无需编译步骤。最小示例：

```typescript
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.registerCommand("hello", {
    description: "Show a greeting",
    handler: async (name, ctx) => {
      ctx.ui.notify(`Hello, ${name || "world"}!`, "info");
    },
  });
}
```

开发时可指定文件加载：`pi --extension ./hello.ts`。

RoughAgent 的能力域插件全部通过该扩展面实现，未修改内核源码。

## 三、内核不提供的部分

官方 Security 文档说明：工具与扩展以 Pi 进程的操作系统权限运行；项目信任只决定加载哪些项目资源，不提供沙箱；扩展是加载进进程的 TypeScript 模块，可以读取 prompts、工具调用、文件、凭据与会话历史。

这些不是缺陷，而是内核的边界：内核不判断“什么算危险”。由此内核之上需要实现的部分是：

- 审批：分级与 fail-closed，见实现说明的第四节；
- 上下文瘦身与跨会话记忆；
- 账单与预算线。

分工是：内核负责机制，应用负责策略。

## 四、与其他 harness 的对比

对比对象为 opencode（v2 分支）与 DeepSeek Harness（DSH）。三者均为 MIT、TypeScript。

![分界线：机制归内核，策略归应用](pi-boundary.webp)
_内核提供机制，应用实现策略，两侧通过扩展面与 SDK 连接_

| 维度 | Pi | opencode v2 | DeepSeek Harness |
|---|---|---|---|
| 定位 | 内核 + 五种接口 + SDK | 完整应用：TUI、桌面端、Web、服务端 | 插件树：agent loop、会话日志、模型适配器均为插件 |
| 默认产物 | 可用的终端 agent；主要产物是 SDK 与五种接口 | 完整开发环境 | 浏览器工作台；默认界面只是一层，主要产物是可替换的插件树 |
| 扩展方式 | extensions / skills / prompts / themes / packages（加载进进程的 TypeScript 模块） | 插件 + 内置 agents（build 全权限 / plan 只读 / general 子代理）+ 权限档位 | Cordis 插件：服务、类型化事件、可逆副作用；用 profile / bundle / patch 组装 |
| 开箱形态 | TUI、print、JSON、RPC、SDK | TUI、桌面端、Web、服务端 | web、headless、sdk、sdk-minimal、acp |
| 会话 | JSONL 树：分支、fork、压缩摘要由文件格式定义 | 会话加 agent 切换 | 会话日志本身也是插件 |
| 嵌入方式 | TS SDK（同进程）、RPC（跨进程）、print、JSON | SDK、server、桌面端 | sdk（JSON-RPC）、headless、acp 三种 profile |
| 版本与规模 | v0.87.1，10.9 万 star | 正式版 v1.18.32，v2 在 v2 分支，21.0 万 star | developer preview（dsh-v0.1.7-rc），23.6 万 star |
| 成熟度表态 | 版本号 0.x，更新频繁 | v2 尚在分支 | 明确标注 developer preview，声明会有破坏兼容的改动，另附 SAFETY 文档 |

表格中四项需要补充说明：默认产物决定上手成本；扩展粒度决定二次开发的上限；开箱形态决定能否直接嵌入现有产品；成熟度表态决定能否作为长期依赖。

“harness”一词目前没有统一定义。本文的判据是：是否把“模型之外的那一层”作为主要工作。按此标准，Pi、opencode、DSH 都属于 harness。

## 五、基于 Pi 的项目

以下是基于 Pi 实现的公开项目（数据截至本文写作时）：

| 项目 | Star | 内容 |
|---|---|---|
| `agegr/pi-web` | 6.9 千 | pi 的 Web UI |
| `vastsa/PI-Desktop` | 5.8 千 | Electron + Rust 宿主的本地优先桌面端 |
| `badlogic/pi-skills` | 2.6 千 | pi 的 skills 包（作者本人的账号） |
| `nicobailon/pi-mcp-adapter` | 1.5 千 | 低 token 开销的 MCP 适配层 |
| `nicobailon/pi-web-access` | 1.5 千 | 联网搜索与正文抽取扩展 |
| `qualisero/awesome-pi-agent` | 1.1 千 | 扩展、钩子、工具、skills 清单 |
| `minghinmatthewlam/pi-gui` | 993 | Electron GUI |
| `rcarmo/piclaw` | 862 | pi 的 Web 界面 |
| `jmfederico/pi-web` | 821 | 在真实工作区中保持会话存活的 Web UI |
| `enderzcx/pi-docs-playbook` | 135 | 面向 agent 的文档导航 |
| `lukasl-dev/pi.nix` | 120 | Nix flake |
| `sky-valley/pi` | 57 | 纯 Go 移植 |
| RoughAgent | — | 本项目：界面、账单、审批、评测、素材管线 |

三点结论：

1. 这些项目集中在界面层：Web UI、GUI、桌面端、文档导航、skills 包、适配层。对内核本身 fork 的项目很少，因为内核功能已由上游覆盖。
2. `sky-valley/pi` 的纯 Go 移植说明：协议对齐后，内核实现可以替换。RoughAgent 此前做过一次内核替换，前端 38 项测试零改动通过。
3. RoughAgent 属于这批项目中功能面较宽的一个（界面、账单、审批、评测、素材管线），实现方式全部是 SDK、事件、会话与扩展面，未依赖内核源码。

## 六、结论

RoughAgent 的内核是 Pi。内核提供 LLM API、agent loop、会话存储、工具执行、上下文压缩与五种接口；应用层提供界面、账单、审批、评测与素材管线。两侧通过 SDK、事件协议与扩展面连接，内核源码未做修改。
