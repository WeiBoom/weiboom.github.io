先说个可能有点扫兴的开场：我做这个东西的起因，不是我想要一个多酷的 Agent。

是因为我心疼钱。

那时候我每天用 AI 写代码，用得挺爽，但每次对话结束，界面上就飘来一行字——「本次消耗 12k tokens」。然后呢？没了。

我不知道这 12k 里有多少真的花在新内容上，有多少是重复付费；不知道是模型在思考慢，还是工具卡住了；更不知道这轮到底花了多少钱，是三分钱还是三毛钱。

我花钱，但看不到账单明细。这感觉很不舒服。

所以 RoughAgent 最早的诉求就两句话：**我想知道自己花了什么，我想用更少的消耗做更多的事。**

后来我把这两句话写进了开发准则里。这篇文章想聊的，就是这两句话怎么一点点变成架构、变成界面、变成屏幕右下角那只小狗的。

## 一、省钱这件事，我认真去查了原理

一开始我以为"省 token"就是少说废话。查了一圈才发现，真正的大头根本不在这儿。

DeepSeek 这类模型的前缀缓存，是按**字节**匹配的。同一个会话，如果这次请求的前缀和上次逐字节一样，那前面这一大段就按很低的折扣价算。但只要前缀变了**一个字节**，对不起，整段从头全额付费。

而市面上很多 Agent 在做什么呢：

- system prompt 里塞一个当前时间戳；
- 把和当前任务八竿子打不着的技能描述全灌进去；
- 工具列表跟着会话开关变来变去；
- 权限档位一改，prompt 跟着改。

每一样都在悄悄把缓存打断。用户看到的是"它怎么又花这么多钱"，看不到的是设计的时候压根没人管过这件事。

我之所以会去看，纯粹是因为我真的在算这笔账。

### 于是有了几条硬规矩

我给自己定了一条，叫**缓存锚纪律**。听着玄乎，其实很朴素：凡是会进请求前缀的东西，都必须恒定。

- 系统提示词里不许出现时间戳、随机 id、"现在是第 N 轮"这种动态拼接；
- 插件开关只对新会话生效，不在会话中途加加减减工具;
- 切换权限档位不进 prompt。

另一条是**前缀瘦身**。Pi 这个内核有个行为，会把跨 Agent 的技能目录无条件拼进提示词。我数了一下，宿主机上那堆跟我八竿子打不着的技能，加起来一万多字符。

关掉之后，稳定前缀从 9,611 tokens 掉到 5,252，少了 45%。

> 没必要的冷启动，我一次都不想付。

还有一条挺有意思的，关于**截断**。大工具结果滑出上下文窗口时会被截断——听起来是坏事对吧？但关键在于它必须是**确定性**的：同一条消息，永远截出同一个形状。这样第一次截断会断一次缓存，之后形状稳定，重新缓存上，长会话总体是赚的。

这个权衡我写在代码注释里了，就是怕以后有人看到"这里断了缓存"当成 bug 顺手"优化"掉。

### 结果是能拿出来看的

不是跑分，是真实用量的账本。有段时间 49 轮真实对话：

- 稳态缓存命中率 **87.2%**，一半以上的轮次命中超过 90%；
- 缓存累计省了 **67%** 的费用——应付 ¥1.92，实付 **¥0.63**。

我一直信一句话：**没有数据的优化等于没发生。** 所以每一轮的用量增量都会落盘成 JSONL。以后谁再说"我这个改动省了 token"，拿出前后的数字来。

## 二、省下来的钱，得让你看得见

省钱和透明，其实是同一件事的两面。你不透明，就不知道自己省没省对。

我不想等到一轮跑完才告诉我"这轮花了多少"。长任务跑一个小时，如果账单一个小时才跳一次，那跟黑盒没区别。

所以 RoughAgent 是**一边跑一边报账**的。

发出消息那一瞬间，界面上就点亮一张实时卡片；之后每一次模型请求发出、每一次返回，金额、上下文占用、请求计数都跟着跳一次。现在跑到第几次请求、这次请求已经跑了多久（超过 30 秒变黄，120 秒变红），全都写在那儿。

正在执行中那个工具，是带读秒的：`grep … 5.0s`。一个长任务到底卡在哪一步，扫一眼就知道。

我特别喜欢的是那个**行为路径**。一轮结束后，它给你列出来的是这个：

```
文本 1.4s → read 137ms → read 132ms → read 1ms
→ write 2ms → open_file 1ms
```

配上"3 个工具 · 6.8s，其中模型耗时 2.0s"，还有平均输出速率 225 tok/s。

这时候你就能判断了：这轮是模型在想事情想得久，还是工具在拖后腿；换个模型、调个思考档位，效果到底有没有变化，数字会告诉你。

![数据总览·轮次面板：单轮的输入/缓存读/输出堆叠、命中率与耗时](round-metrics.png)
_数据总览·轮次：单轮的输入／缓存读／输出堆叠，加上命中率、请求次数与耗时_

顺手说个坑。数据面板的命中率口径，一度写错过——把命中量在分母里算了两次，结果算出来的数比真实值偏小。这种地方不较真，你看到的"优化成果"就是假的。

还有一个我一开始没考虑到的地方：**子代理**。当主 Agent 把任务委托出去，烧的 token 其实不少。现在只要"子代理运行中"亮起来，每次子请求结算都会实时入账。并行委托的花销，也不再是黑盒了。

对了，还有两道保险：上下文按近期增速预估"大概还有 N 轮就要压缩"，长会话心里有数；再设一条会话或每日的预算线，超了就弹一下。

一句话——**别人只告诉你结果，我想让你看见 Agent 此刻在干什么、烧到哪了。**

## 三、几条我改代码时不会让步的准则

做了这么久，有几条规矩是刻在墙上的。写在这儿，也是给自己以后留个提醒。

**第一，绝不改内核源码。**

Agent 的循环、工具执行、上下文压缩这些，跑在 Pi 内核上，版本精确锁定。所有定制都走它开放的 SDK 和扩展面。为什么？因为改源码一时爽，跟上游就变成了长期噩梦。现在的状态是：升级内核基本就是改个版本号，加跑一遍全量测试。

这套约束真的被检验过一次。内核被整体替换的那天，前端 38 项测试**零改动全过**。

靠的是什么？**前后端之间只有一份事件协议当契约。** 内核的差异，全被一个文件吸收掉了。前端根本不知道底下换过引擎。

**第二，机制归内核，策略归我们。**

审批要分级、上下文要瘦身、要记住跨会话的偏好——这些是我们的事。但实现它们的工具怎么执行，是内核的事。分工清楚，才不会有那种"哪里都能插一脚"的乱麻。

顺带一个我挺得意的设计：内置能力和第三方插件，走的是**完全同一条注入管线**。没有"亲儿子代码路径"。想加个工具？插件目录丢一个文件就行。想接个新模型商？GUI 里建个档案，一行业务代码都不用动。

![插件面板：内核注册的 11 个能力域插件，开关只对新建会话生效](plugin-panel.png)
_插件面板：内核已注册 11 个能力域插件，开关只对新建会话生效，第三方插件走同一个 PluginHost_

**第三，失败要关门，不要开门。**

所有审批路径都是 fail-closed 的。桥没挂上，拒；120 秒没响应，自动拒；一个回合收尾了还没批，统一拒。听起来很严格，但安全这东西，宁可错拒，不能错放。

![ask_user 批量抉择卡片：多个问题合并，确认后一并提交](ask-user-batch.png)
_审批走 ask_user：多个问题合并成一次抉择，选完再一并提交_

**第四，没有数据的优化，不算优化。** 前面说过了，再说一遍也不嫌多。

**第五，测试不全绿，不算做完。** 而且我尽量让测试不花钱——用本地的假模型服务把开发、联调、集成测试都覆盖了，跑一次回归不用掏一分钱。不然"每次改完都跑全量测试"这种话，谁做得到。

## 四、它其实有三个壳，但是同一个它

这是我后来才意识到挺费心、也挺值的一件事：桌面端、浏览器、终端，**不是三个软件，是同一个 Agent 的三个壳。**

同一个服务跑在本地，三个入口进：

- **桌面端**，Tauri 做的无边框窗口，是我的主力工作台，带会话管理和数据面板，还有个独立的桌宠小窗；
- **浏览器**，打开同一个端口就能用，随手开个标签页；
- **终端**，键盘流的 TUI，读的是同一份配置。

同源到什么程度呢——**你在终端里聊的会话，桌面端的侧边栏看得见、能接着聊；反过来也一样。** 你在 GUI 里换的模型，终端里接着就是同一个。

说实话，第一次在终端里看到几小时前在 GUI 里聊的那段对话，是有点感动的。

## 五、屏幕右下角那只小狗

接下来聊点不那么技术的东西。

桌宠叫**丢丢**，是真狗的名字。

我有一段远程加班的日子，家里只有我和它。熬夜改 bug 的每个凌晨，它都趴在我脚边。它当然不懂什么是 CPU、什么是缓存，也不懂我为什么对着一个红色堆栈皱眉——但它知道我还在，所以它也不睡。

后来我想，既然它总在，不如把它做进去。

所以 RoughAgent 右下角那只像素小香槟色的狗，就是它。

严格说，桌宠是个"状态可视化设备"：它会在你打字时安静待命，在模型思考时趴下歪头，在工具跑起来的时候迈小碎步，在等你审批的时候坐直了盯着你，出错时一脸委屈（而且这个状态是粘性的，不会一闪而过让你看不见），任务完成就摇尾巴庆祝。

**Agent 在干什么，看一眼它的姿势就知道了。** 不用去翻日志。

![桌宠预览：思考中的丢丢，以及六种状态切换](doudou-preview.png)
_桌宠预览：待命中／思考中／执行工具／等你批准／出错了／搞定啦_

技术上有几个细节我是较真的。它用的是 CSS 精灵表驱动动画，`steps()` 的采样点为什么这么取，我写在注释里了（`jump-end` 会错位半帧这种事，不写下来下次还会踩）。系统开了"减少动态效果"时，它不会直接僵住，而是变慢。图片加载失败，会自动降级成单帧。

还有个事我一直记得。早期 AI 生成的那批精灵图，网格整批错排，查了半天根因——是我用了"生成器自己验自己"的同义反复测试。从那以后资产管线加大了一批确定性质检，还有一道 ASCII 目检的门禁。

它不会掉毛，不会半夜扒门，也不会因为我加班太久饿肚子。但我在屏幕角落看它迈小碎步的时候，总觉得那个陪我到凌晨四点的家伙还在。

## 六、外观：两套皮肤，和一条"不许写 JS"的规矩

界面上我有两套视觉：**像素风**和**现代风**。

像素风是切角窗口、阶梯阴影、点阵标题、8×8 网格图标，一股上世纪的劲儿；现代风是圆角、细描边、24×24 线性图标。

![像素风与现代风并排对比：同一套组件，两种观感](cover.png)
_两套皮肤并排：左像素风、右现代风，组件样式一行都不重复_

做这个的时候我犯过一个错：一开始不叫"皮肤"，我叫它"双人格"。后来发现这个比喻很糟糕——"人格"会让人以为这个 App 有两个可切换的 AI 身份，那是完全另一回事。代码里也没有第二个 persona，它俩就是同一套功能的两种观感。我老老实实改回"皮肤"了。

实现上没有维护两套样式表。现代风其实只是一层**观感原语覆盖**（圆角、阴影、字体栈），组件样式一行都不重复。38 个通用图标，每个都同时定义了像素网格和 SVG 描边两套画法，品牌图标也一样。切换是即时的。

后来皮肤做成了可以外挂的。**一个目录 + 一个 skin.json**，丢进去就能用，还能分三级：只换配色、加换造型、或者整个界面重做。

![外观设置：皮肤从目录安装、界面主题、界面风格、背景与桌宠表现](appearance-settings.png)
_外观设置：皮肤可从目录安装，主题／风格／背景／桌宠表现都在这一屏_

这里有条硬规矩：**皮肤包里不许有可执行代码。**

```
js / script / eval / entry / import / require ...
```

出现这些字段会被明确拒绝，不是忽略。

为什么？换来两件事。一是**皮肤包可以放心分享**——装一个包不等于装一段来路不明的程序；二是**卸载能保证干净**——没有 JS，就没有那些"作者自己加的、我们不知道的副作用"要收拾，运行时对界面做的事全部可枚举，卸载就是逐一收回。

说实话，我觉得大多数"插件系统"都栽在这上面：为了灵活，什么都放进来，最后没人敢装别人的包。

## 七、它现在是块石料，还远没到最好的样子

写到这里得说句实在话：RoughAgent 现在能用，但离"完成"差得远。

我给它起这个名字，是因为我的工作室叫 RoughStone——一块未经打磨的原石。它可以是铺路的碎石，也可以是压箱底的璞玉，磨开之前谁也不知道。

这个名字我喜欢的地方在于它**不预设结果**。

所以代码里那些"为什么这么写"的注释，那些坦白的边界（比如三端目前只有配置和内容是同源的，工具面还没完全对齐），都不是"已经完美"，而是"这里还没打磨完"的标记。

它有更远的目标：将来成为自研引擎 RoughEngine 的专属开发 Agent。现在预留的引擎扩展面、终端那个壳，都是为那一步铺的路。

在那之前，它就是我的个人 Agent：跑在我自己的电脑上，数据在我手里，服务只监听本机，缺什么我自己给它加，它记得我的项目，也会用一种挺较真的方式告诉我它花了多少钱。

---

## 写在最后

回到开头那个有点窘迫的动机：AI 太贵，我想知道钱花在哪。

现在我可以回答了。每一次请求花在哪、缓存命中多少、工具跑了多久、贵在思考还是贵在执行，屏幕上都有。

这大概就是我做这个东西最想守住的东西——**不是让它看起来更聪明，而是让它更诚实。** 对自己花了多少钱诚实，对做得到什么、做不到什么诚实。

石头还没磨亮。但有人在旁边陪着。
