## 一、先说"Rough"是什么意思

**Rough 不是粗糙，是"有待打磨"。**

**RoughStone** 是我个人工作室的名字。它指的是一块未经打磨的原石——

> 它可以是普通的石头，也可以是亮眼的璞玉。
> 这意味着无限的希望，也意味着无限的可能性。

这个名字我很喜欢，因为它不预设结果。一块石头，最后是铺路还是成器，取决于有人愿不愿意磨它。RoughAgent 就是这块原石上磨出来的第一个作品，而它本身也还是块石料——**能用，但远没到最好的样子**。

所以这个项目里的每一条取舍、每一句"为什么这么写"的注释，都不是完成态，而是"待打磨"的标记。

## 二、为什么我要自己做：AI 太费钱了

事情的起点很朴素，甚至有点窘迫：

**AI 太贵了。**

我用过不少 Agent 工具。它们确实能干活的，但每次对话结束，我就只看到一行"本次消耗 12k tokens"——然后呢？

- 这些 token 花在了哪里？
- 有多少是缓存命中的（便宜的），多少是全额付费的？
- 是模型在思考，还是在执行工具？慢在哪一步？
- 我这一轮到底花了多少钱？

**我花钱，却不知道钱花在了什么上。** 这是个让人不舒服的状态。

于是我给自己定了两条最朴素的诉求：

> **一、我想知道自己花了什么。**
> **二、用最少的消耗，做更多的事。**

这两句话看着简单，但它直接决定了 RoughAgent 的整个架构——不是做一个"省流模式"开关，而是**把省钱写进设计准则**。

### 然后我发现，很多人不知道的事

前缀缓存（Prefix Cache）是按**字节**匹配的。也就是说：**请求前缀每变一个字节，整个会话的缓存从零开始，全额重付。**

而大多数 Agent 在干什么？

- 在 system prompt 里注入当前时间戳；
- 把和当前任务无关的技能描述全塞进去；
- 让工具列表随会话开关变化；
- 权限档位一改，prompt 跟着变。

**每一样都在悄悄打断前缀缓存。** 每一次请求，都全额付费。

这不是"用户不小心"，这是设计时就没考虑过的问题。而我去看了，只是因为我真的心疼钱。

## 三、什么是"个人 Agent"

市面上的 Agent 大多想做成"通用的、给所有人用的产品"。

RoughAgent 不是。它一开始就只为一件事而生：**给我自己用。**

这不是格局小，而是取舍：

| 通用 Agent | 个人 Agent（RoughAgent） |
|---|---|
| 讨好所有人，功能大而全 | 只服务我，功能围绕我的工作流长出来 |
| 数据在云端，账号在别人手里 | 数据在我磁盘上，服务只监听 `127.0.0.1` |
| 定制要走需求排队 | 缺什么就当场写个插件给自己 |
| 不认识我 | 记得我的项目、我的习惯、我的工作目录 |

**"个人"不是形容词，是架构约束。**

因为只服务一个人，所以它可以：

- 把 API Key 只存自己磁盘，服务只绑 `127.0.0.1`，不需要任何云端账号；
- 我的工作目录、我的项目注册表、我的会话历史，都是本地一份；
- 缺一个工具，我就写一个插件丢进去——**它长成了我手的样子**。

## 四、它长什么样：三端共享，一个核心

RoughAgent 最容易被低估、也最费心的一件事：**桌面、浏览器、终端，是同一个 Agent 的三个壳，不是三个软件。**

同一个 server（`127.0.0.1:8787`），三个入口：

| 端 | 形态 | 定位 |
|---|---|---|
| **Desktop GUI** | Tauri + 无边框窗口 | 主力工作台：会话管理 + 数据总览 + 桌宠独立小窗 |
| **WebUI** | 浏览器打开同一端口 | 零安装即用，随手开个标签页就能聊 |
| **TUI** | 终端里的 pi CLI | 键盘流、极客感，未来要嵌进 RoughEngine 当控制台 |

### 三端同源到什么程度

- **配置面同源**：三端共用同一个 Pi 配置目录与同一份模型档案投影。你在 GUI 里换的模型、调的思考档位，终端里接着就是同一个。
- **内容面同源**：三端共用会话目录与项目注册表。**你在终端里聊的东西，GUI 里必须看得见、能续聊。**

因为定了条铁律：**17 种 AgentEvent 协议是前后端唯一契约**，内核差异全部被一个 `pi-host.ts` 单通道文件吸收。前端永远不知道底下是什么引擎。

> **诚实边界**：同源的是配置与内容。**工具面目前仍不同源**——GUI 注入 6 个内置 gate + 外部插件，TUI 只加载审批门控。这不是隐瞒，是待办清单上的一条。

## 五、把"省钱"做成架构

这是 RoughAgent 最核心的差异点。

**前缀缓存命中率不是事后统计的指标，而是写进设计准则的一等公民：**

- **锚定纪律**：系统提示词是恒定常量，不注入时间戳；插件开关不随会话变化；权限档位切换不进 prompt。任何会改变"请求前缀"的东西，都被隔离在会话生命周期之外。
- **45% 的前缀瘦身**：默认屏蔽跨 Agent 技能目录的无差别注入（实测 10.7k 字符），把稳定前缀从 9,611 tokens 砍到 5,252。**没必要的冷启动，一次都不要付。**
- **聪明的截断**：大工具结果滑出上下文窗口时做确定性截断。首次截断会断一次缓存（每条大消息只断一次），之后形态稳定重新缓存——长会话净收益为正。

**实测战绩**（真实用量，不是基准测试）：

> 49 轮真实对话，稳态缓存命中率 **87.2%**，其中 57% 的轮次命中 90% 以上；
> 缓存累计节省 **67% 费用**——应付 ¥1.92，实付 **¥0.63**。

我信奉一条准则：**没有数据的优化等于没发生。** 每一轮的用量增量都会落盘成 JSONL，任何优化都要拿 before/after 数据说话。

注意最上面那个**绿色框：`本轮已完成 已完成 6 次请求`**。这是本轮结束后的总结态——卡片不会消失，留住这一轮的全部账单：

| 指标 | 数值 |
|---|---|
| 输入 | 12.5K |
| 缓存读 | 112.0K |
| 输出 | 5.6K |
| **本轮命中率** | **90%** |

| **输出速率** | **225 tok/s** |
| **本轮费用** | **¥0.026** |
| 会话累计 | ¥0.070 |

下面那张表是**模型行为路径**——它精确告诉你时间花在哪：

```
文本 1.4s → 4ms
read 137ms → read 132ms
read 138ms → read 1ms
read 1ms  → write 2ms
open_file 1ms
```

**"9 次工具调用、24.9 秒"不是一句模糊的总结，是一条条列出来的。** 其中模型输出 225 tok/s，模型耗时 24.9s——一眼就能看出这轮到底是"模型在思考"还是"工具在跑"。

再往下是上下文与缓存：

- 占用 `29.0K / 1.0M`，剩余 `971.0K`，使用率 `3%`，压缩次数 `0`，`≈ 68 轮后压缩`——长会话心里有数；
- **缓存命中率 83%**，旁边是像素格的命中率热力条。

输入框右下角还有一行常驻：`29.0K / 1.0M` 上下文 · 余额 `¥55.25` · 累计 `¥0.0704`。

> **别人只告诉你结果，RoughAgent 让你看见 Agent 当下在干什么、烧到哪了。**

### 而且观测不必等轮末

发出消息的那一瞬间，`usage_delta` 事件就把实时轮次卡片点亮；之后每次模型请求发出/返回，金额、上下文占用、请求计数随每一次调用跳表：

- "第 N 次请求进行中"、当前请求已耗时（超 30s 变黄、120s 变红）；
- 正在实时追加的行为路径，进行中的工具以黄色虚线框标注；
- 子代理烧的 token 同样实时入账——"子代理运行中"一亮，每次子请求结算即跳表，并行委托的花费不再黑盒。

轮子跑完，卡片转入绿框 **"本轮已完成"**，直到你开始下一轮。

## 七、桌宠丢丢：陪我熬夜写代码的那只小狗

严格说，桌宠不是吉祥物，是**状态可视化设备**。但对我个人来说，它其实是另一件事。

它是我的小狗，**丢丢**。

![丢丢 —— 右下角那只「思考中」的小狗，正陪我改这篇文章](doudou-thinking.png)

### 丢丢是只什么样的狗

**聪明，调皮，还特别黏人。**

它会在你打字打得正入神的时候，一屁股坐到你脚边；会在你盯着报错发呆的时候，用鼻子顶一下你的手背，提醒你该摸摸它了；也会在你根本没空理它的时候，自己找个角落躺下，安安静静地看着屏幕上的光标跳。

我做远程加班那段时间，家里只有我和它。**熬夜通宵改 bug 的每一个深夜，它都陪着。** 它不懂什么是 CPU、什么是缓存命中率，也不懂我为什么对着一个红色堆栈皱眉头——但它知道我还在，所以它也不睡。

后来我想，既然它总是在，那不如把它做进产品里。

于是有了这个桌宠：像素小香槟色的丢丢，桌面端是一只独立的透明置顶小窗，拖到屏幕任何角落都行。**它坐在那里，就是我工作状态的一部分。**

### 它现在在替我做什么

在新截图里，它就是右下角那只小狗，头顶气泡写着 **「思考中」**——那是它当前的状态播报。

| 状态 | 丢丢在做什么 | 触发时机 |
|---|---|---|
| `idle` | 待命、发呆、歪头看你 | 你空闲时 |
| `thinking` | 趴下思考，耳朵一动一动 | 模型推理中 |
| `running-tool` | 迈开小碎步（帧率对齐步频 12fps） | 工具执行中 |
| `waiting-approval` | 坐直了盯着你 | 等你审批时 |
| `error` | 一脸委屈（粘性，不会一闪而过） | 报错时 |
| `done` | 摇尾巴庆祝（播放两遍后停在末帧） | 本轮结束时 |

**Agent 在干什么，丢丢就表现成什么样子。** 你不用去看终端日志，看一眼丢丢的姿势就知道它是在思考、在跑工具、还是卡住等你了。

### 一些技术上的讲究

- **双形态**：桌面端是独立的透明置顶小窗（176×208），拖到屏幕任何角落都行；浏览器里收敛为页内挂件。两形态共享同一个**纯函数状态机**。
- **和身份解耦**：丢丢是独立的形象层，不影响 Agent 身份，也不污染模型品牌标识。
- **科学驱动**：动画全部用 CSS 精灵表，`steps(6, jump-none)` 的采样点论证写在注释里（为什么 `jump-end` 会错位半帧）；系统开了"减少动态效果"时降级为慢速而非静止；精灵图加载失败自动降级单帧模式。
- **健壮管线**：AI 生成的精灵图网格曾整批错排，根因是"用生成器自己验自己"的同义反复测试。此后资产管线加了十维确定性质检 + ASCII 目检门禁。

### 它和真的丢丢

它不会掉毛，不会半夜扒门，也不会因为我加班太久而饿肚子。

但我看着它在屏幕角落迈小碎步、歪头等我做决定的时候，总觉得那个陪我熬到凌晨四点的家伙还在。

**Agent 的黑盒感，被一个会看你的小生物消解了。**

## 八、对话框：像聊天工具，但有信息层级

对话区不是"命令行回显"，而是有明确信息层级的：

- **用户消息右对齐**（带你的头像与时间戳），**模型消息左对齐**（带模型品牌标与时间戳）；
- **思考过程**独立成块，与正文分离；
- **工具调用折叠**成一行摘要（`本轮工具调用 · 9`），点开看细节，不刷屏；
- **文件修改**单独成卡：显示 `write` + 路径 + 「打开」「在文件夹中打开」；
- **抉择对话框**：`ask_user` 工具直接把选项渲染成卡片，选中即回传；
- **审批对话框**：待审批时挂起并弹出确认，120s 无响应自动拒绝；
- **输入框**：`Ask anything, / for commands, @ for context, paste or drop images...`——支持 `/` 命令、`@` 引用上下文、粘贴或拖入图片。

配套三颗状态 pill：**自动执行**档位、**思考**档位、**模型选择**（`deepseek-flash`），加一个发送按钮。

## 九、自定义：长成你自己的样子

| 可自定义项 | 说明 |
|---|---|
| **模型档案** | 任意 OpenAI 兼容端点（DeepSeek / Kimi / GLM / 豆包……），一档挂多个子模型随时切 |
| **思考档位** | 关 / 低 / 中 / 高，激活档案默认值 + 对全部活会话实时生效 |
| **权限档位** | auto / 写确认 / 全审，热切换即时生效 |
| **头像库** | `web/src/data/*.json` 可配置目录（动漫职业 / 头像库 / 模型品牌），新增条目只改 JSON 不动代码 |
| **主题人格** | 像素风 ↔ 现代风一键切换，观感原语覆盖，组件样式零重复 |
| **桌宠** | 独立透明小窗，可拖拽到任意角落，形象可换 |
| **记忆** | 跨会话记忆（JSONL + 关键词检索），新会话不失忆 |
| **插件** | 放个文件即扩展，与内置能力走同一条管线 |

**身份语义分离**：大模型品牌标与用户头像库彻底解耦——你选什么头像都不会污染模型身份标识。

### 扩展不改源码

四层扩展体系汇入同一个注册表，**没有亲儿子代码路径**：

| 你想扩展什么 | 要动几处 |
|---|---|
| 加一个工具（第三方插件） | **1 处**：插件目录放 manifest + 入口文件 |
| 加一个 LLM 供应商 | **0 处**：GUI 建档即接入 |

内置的能力域（审批门、抉择门、上下文管家、记忆、文件打开、引擎桥、子代理）与外部第三方插件，走完全相同的注入管线。

甚至**默认关闭的子代理**，关闭理由都写在注释里：独立缓存锚会断、token 总账会涨——开启前你会知道代价。

### 安全模型

- 审批链全路径 **fail-closed**：桥未挂载即拒绝、120 秒超时即拒绝、回合收尾统一拒绝，不存在"挂着没人管的放行窗口"；
- 服务只监听 `127.0.0.1` + 三重鉴权；
- **API key 只进内存，不落 auth.json**。

## 十、底座：为什么是 Pi 内核

RoughAgent 的 Agent 循环（工具执行、上下文压缩、会话持久化）跑在 [Pi 内核](https://github.com/earendil-works/pi-coding-agent) 上，**精确 pin 版本**。

这背后是整个项目最重要的两条架构决策：

1. **17 种 AgentEvent 协议是前后端唯一契约。** 内核差异全部被一个 `pi-host.ts` 单通道文件吸收，内核升级 = 改一个文件的适配层，前端永远不知道底下换过引擎。
2. **永不修改 Pi 源码。** 所有定制走 SDK 扩展面注入。这让"跟上游"从噩梦变成日常——升级成本被锁死在防腐层内。

这套约束经历过一次真实检验：内核曾整体替换过，**替换那天，前端 38 项测试零改动全过**。

桌面端是 Tauri + Rust，但 Rust 侧刻意薄到只做三件事：进程治理（sidecar 探活复用、Windows Job Object 强杀回收、5 秒看门狗）、双窗口、托盘。**业务逻辑一行都不下沉。**

## 十一、它为什么存在：为 RoughEngine 而生

RoughAgent 有一条更远的路线：

**它不只是"我用的 Agent"，它是为自研引擎 RoughEngine 而扩展出来的 Agent 工具，未来会成为 RoughEngine 的专属核心开发 Agent。**

这意味着几件事：

- **现在**：它是我的个人 Agent，服务我当下的开发工作——读代码、改代码、写文档（比如这篇文章）、跑工具。
- **未来**：当 RoughEngine 成形，RoughAgent 会成为它的**核心开发伙伴**——理解引擎的代码结构、参与引擎的迭代、甚至作为引擎内部控制台的一部分（TUI 端已经在为这条路线预留位置）。
- **架构上**：今天留的"引擎域"扩展面（engine-gate 两阶段协议）、RPC 守护进程通道，都是为这一步铺的路。

所以 RoughAgent 不是一个终点产品，**它是一块正在被磨的原石**——磨它的人是我，而它将来要服务的那台引擎，也还是块原石。

这大概就是"Rough"最完整的含义。

## 写在最后

回到开头那两个字。

**Rough 不是粗糙，是"有待打磨"。** 它承认自己现在不够好，但也拒绝被定性——一块原石可以是铺路的碎石，也可以是压箱底的璞玉，在磨开之前谁也不知道。

我做 RoughAgent，起因只是"AI 太贵了，我想知道钱花在哪"，以及"我想用最少的消耗，做更多的事"。结果这两句话推着我把它做成了一个**独属于我自己的 Agent**：它跑在我电脑上，数据在我手里，缺什么我自己给它加，它记得我的项目，它还会用一篇文章告诉我它是谁。

而屏幕右下角，坐着丢丢。

它不真的懂我在写什么，就像真的丢丢也不懂。但当我敲下最后一行、它摇着尾巴把那一格动画停下来的时候，我总觉得，这个深夜不算太难熬。

这台引擎的下一站，是成为 **RoughEngine 的专属核心开发 Agent**。

这条路还长，石头也还没磨亮。但有人在旁边陪着。

> **RoughStone —— 未经打磨的原石，意味着无限的希望，也意味着无限的可能性。**
